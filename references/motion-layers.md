# 动效分层与成本控制

**这是本 skill 最重要的成本机制，请务必读完。**

---

## 一、核心原则

> **AI 视频只在「运动本身就是知识点」时才必要。**

科普片里绝大多数镜头，观众看的是**结构**（这是什么、怎么连的、部件在哪），
不是**运动**。这种情况下用 AI 生成视频是纯浪费：
- 花钱（79 积分/段）
- 耗时（20~60 秒/段）
- 还会**把观众注意力从结构上带走**（AI 生成的运动会乱动）

用代码做的高亮圈 + 推镜，反而**更精准**、**零成本**。

---

## 二、三层动效

| 层 | `motion.type` | 手段 | 成本 | 什么时候用 |
|---|---|---|---|---|
| **静止层** | `still` | 静态底图 + Remotion 代码动效（推镜/高亮/标注） | **0** | 结构图、剖面图、流程图、对比图、层级图 |
| **精确层** | `precise` | 代码渲染的确定性动画 | **0** | AI 做不了的精确状态（阀门精确转 90°、水位到指定刻度） |
| **AI 层** | `ai` | minimax/h3 首帧驱动 | **79 积分/段** | **只有**运动本身是知识点时 |

### 判断标准（问自己三个问题）

1. **把这一拍换成静态图 + 高亮框，观众还懂吗？**
   → 懂 → 用 `still`（大概率）
2. **这个运动是本拍要讲的知识点本身吗？**
   → 是（流体流动、阀门开启、分子振动、相变、爆炸展开）→ 用 `ai`
3. **这个运动有精确的起止状态吗？**
   → 有 → 用 `precise`（代码画），AI 做不准

## 三、★ 第四种形态：**混合架构**（AI 视频底 + 代码精确层）

这是 2026-11-04 实测出来的、目前**效果最好**的形态，也是本 skill 的默认推荐。

### 为什么需要它

单用 AI 视频，单用代码，**都会出硬伤**：

| | AI 视频（h3） | 纯代码 |
|---|---|---|
| 有机运动（软组织形变、血流、材质） | ✅ 质感自然、有生命力 | ❌ 呆板，像 PPT |
| 几何/状态精确（瓣膜真的开合、相位对齐） | ❌ **做不到** | ✅ 精确 |
| 文字标注 | ❌ **会扭成乱码** | ✅ 精确 |
| 成本 | 223 积分/12 秒 | 0 |

实测证据（心脏样片）：
- AI 视频的**心肌搏动是真的**：逐帧像素分析测出 2.0 秒/次的稳定周期，
  深蓝腔面积波动 12.5%，帧差热力图显示变化集中在心室区而画面边缘为 0
  （= 真局部搏动，不是整体推镜）。
- 但 AI 的**瓣膜是静态奶白结构**，帧差热力图上瓣膜区几乎无变化 → 不会真开合。
- AI 的**房室收缩没有严格时序**：实测右心室腔周期 2.0s、右心房腔周期 1.0s，
  心房并没有「先于心室」收缩。旁白说「心房先收缩」时画面不支持这句话。
- AI 的**解剖左右会画反**（3D 医学图高发），必须人工核对 + 镜像修正。

### 正确分工

```
底层：AI 视频   → 有机运动、软渲染质感、血液流动
叠加：代码层     → 精确状态（瓣膜开合）、相位标签、全部文字标注
```

叠加层要做的四件事：
1. **全部文字**（AI 会把字扭成乱码，一个字都不能给它）
2. **AI 做不出的精确状态**（瓣膜开合小窗、阀门角度、水位刻度）
3. **相位对齐的标签**（节律条、相位文字，用**实测**的搏动周期驱动，不是猜的）
4. **引线锚点用 AI 视频帧的坐标**（AI 重绘后构图与原底图不同，原图坐标会指错）

### 参考实现

`templates/remotion-project/src/HeartAI.tsx` —— 心脏 apiz 生视频路线样片
（底图 Flare 60 积分 + h3 12s 768P 223 积分 + edge-tts 免费）

配套脚本：`examples/heart-ai/gen_heart_ai.py`（生图）、`gen_video.py`（生视频，带台账幂等）。

### ★ 关键手法：先测 AI 视频的真实节律，再让代码层跟着它走

不要凭感觉写节律。步骤：

1. 抽帧序列（`ffmpeg -vf fps=12`）
2. 选一个**干净的判别区**（例：右心室腔的深蓝像素面积）
3. 逐帧统计面积随时间的变化 → 找出周期和相位
4. 把这个周期写进代码层的相位函数，标签/小窗就与画面天然同步

本 skill 实测结论：
- 右心室腔周期 = **2.0 秒**，谷底（腔最小＝心室收缩）在 t = 0.5, 2.5, 4.5…
- 收缩期 = 周期内 t∈[0.25, 0.75] → 房室瓣在此期间关闭

## 三之二、第五种形态：整段代码场景（`custom`）

上面三层解决的是**「一拍的动效」**。有一类镜头需要的不再是一拍，
而是**一段连续、严格按相位同步的复杂运动**：

| 场景特征 | 例子 |
|---|---|
| 有确定的周期相位 | 心动周期、振荡、驻波、循环流 |
| 多个部件必须**严格按相位互斥/先后** | 房室瓣 vs 半月瓣、进气 vs 排气 |
| 几何关系每帧都要正确 | 血流方向、腔壁厚薄、开口大小 |

这种镜头**既不该用静态图 + 高亮，也不该用 AI 视频**：

- 静态图表达不出「运动」
- AI 视频模型做不了「严格按相位对齐、每帧几何都正确」——它会让血液流向乱、
  收缩顺序错、瓣膜半开半关

**正确做法：直接写一个 Remotion 组件，用 SVG + `useCurrentFrame()` 把整个场景画出来。**
零积分、可无限次调参、几何永远正确。

参考实现：`templates/remotion-project/src/HeartCycle.tsx`
（心脏复杂工作原理，12.25 秒，0 积分 —— 四腔搏动 + 瓣膜相位开合 + 红蓝血流 + 同步 ECG）

### 关键手法

| 需要什么 | 怎么写 |
|---|---|
| 时间 → 生理状态 | 相位函数 `p = (t / CYCLE) % 1`，配高斯凸起算收缩强度 |
| 某段路径在流动 | `pathLength={1000}` + `strokeDasharray` + 负向 `strokeDashoffset` |
| 「此刻该亮/该流」 | 用相位函数算一个 0~1 的 `active` 传给 `strokeOpacity` |
| 开关型部件（瓣膜） | 两片叶子，端点随 `open∈[0,1]` 在「中心合拢」与「贴壁让开」间插值 |
| 周期波形（心电） | 生成若干周期的 `polyline` + `translate` 滚动 + `clipPath` 裁剪 |

### 写代码场景时的版面纪律（都是实测踩出来的）

1. **SVG 元素必须包在 `<svg>` 里**。直接写 `<text>`/`<rect>` 会被当成未知 HTML 标签，
   **画面全空且 React 不报错**。症状：成片体积异常小。→ 改完必须抽帧目视。
2. **图上不写长名称标签**。相邻部件横向只差几十 px，4 字名牌必然重叠。
   → 图上放**编号徽章**，名称 + 实时状态放底部面板。既不挤，又多一层教学信息。
3. **面板元素按实际文字宽度排**。4 字名 vs 3 字名用同一个偏移 → 圆点压在字上。
4. **「壁」与「腔」分开缩放**。同步缩放会让腔读成「漂浮的小方框」。
5. **不要用纯白表示腔**。白色会被读成「这里是空的」。腔用浅血色调，壁用深一档。
6. **先定版面分区，再画内容**。标题 / 相位框 / 主体 / 波形条 / 状态面板 / 图例 / 字幕，
   自上而下各占一条带，垂直不重叠。

## 四、什么该用 AI 视频（真例）

| 场景 | 为什么必须用 AI |
|---|---|
| 流体在管道里**流动** | 流动本身是知识点，静态图表达不出「在流」 |
| 阀门**开启**的过程 | 过程是知识点（机械动作） |
| 分子**振动** / 粒子运动 | 微观运动无法用静态图表达 |
| **相变**（水沸腾成汽） | 形态渐变是核心 |
| **爆炸/解体**展开 | 结构变化过程本身是知识点 |
| 物体**下落/弹跳**轨迹 | 运动轨迹是信息 |

## 五、什么**不该**用 AI 视频（真例）

| 场景 | 用 still 就够 | 原因 |
|---|---|---|
| 管道剖面结构 + 讲各部件 | 高亮框逐个点名部件 | 观众看的是「哪里是哪里」 |
| 信号通路图 + 讲级联顺序 | 标注按顺序依次出现 | 静态图 + 顺序标注更清楚 |
| 细胞结构图 + 讲 organelles | 高亮各结构 | 结构位置是信息 |
| 实验流程图 + 讲步骤 | 步骤标注依次点亮 | 流程图本来就是静态的 |
| 两种方案对比图 | 高亮差异处 | 对比靠的是并置，不是运动 |
| 数学证明图 | 代码精确渲染 | AI 画不准几何 |

> **科普片里 AI 视频的合理占比：通常 15%~30%。**
> 超过 50% 基本意味着在浪费钱。

## 六、静止层怎么做出信息量

`still` 不是「一张死图」，它有三种代码动效，可叠加：

### 1. 推镜（zoomTo）

把观众视线收到该看的地方。镜头在前 70% 完成，后段稳住给观众看清。

```json
"motion": {
  "type": "still",
  "zoomTo": {"x": 500, "y": 220, "scale": 1.25}
}
```

坐标用**千分比**（0~1000），换画幅不错位。

### 2. 高亮框（highlight）

精确指向正在讲的部件，带标签和脉冲。**AI 做不到这么准。**

```json
"motion": {
  "type": "still",
  "highlight": {
    "x": 500, "y": 220, "w": 190, "h": 130,
    "label": "阀门手轮",
    "delay": 1.2,
    "duration": 4.5,
    "color": "#ef4444"
  }
}
```

| 字段 | 说明 |
|---|---|
| `x`/`y` | 中心点，千分比 |
| `w`/`h` | 框宽高，千分比 |
| `label` | 框下方的标签文字 |
| `delay` | 出现延迟（秒），对齐旁白节奏 |
| `duration` | 保持时长（秒），到点淡出 |

### 3. 标注层（annotations）

多个文字标注按旁白节奏依次出现（见 plan 字段说明）。

## 八、流程上的强制卡点

1. **`gen_animations.py` 只处理 `motion.type == 'ai'` 的拍**，
   其余直接跳过并打印说明。
2. **`plan_schema.py` 校验**：
   - `motion.type='still'` 却写了 `animation.prompt` → **报错**
     （这段提示词永远不会被用，是浪费）
   - `motion.type='ai'` 却没写 `animation.prompt` → **报错**
3. **`estimate_cost.py` 花钱前先算账**，
   如果 AI 占比 > 50% 会明确警告。
4. **`build_storyboard.py` 打印实际动效分布与成本**。

## 十、⚠️ 一个真实教训

本次改造前，pipeline 把「每拍都出 AI 视频」写死了。
跑一个 3 拍的测试集，就烧掉 91 积分（其中 3 张底图只占 18），
**73% 的钱花在了「其实静态图就够」的镜头上**。

写 plan 时先问一遍：**这一拍的运动，是知识点吗？**
不是 → `still`。
